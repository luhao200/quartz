## Context

当前仓库仍以 Quartz 默认三栏布局为主：`quartz.layout.ts` 在内容页左侧放置 `PageTitle + Search + Darkmode + ReaderMode + Explorer`，右侧放置 `Graph + TableOfContents + Backlinks`，全站 `afterBody` 还会追加 `RecentNotes`。`content/index.md` 仅提供文本型欢迎页，站点没有固定顶部导航，也没有首页 Hero、精选文章或按页面类型区分的展示密度。

这次变更同时涉及配置入口、布局组件、全站样式和内容目录迁移，属于跨模块调整。仓库现状也决定了几个约束：
- `QuartzConfig` 类型是封闭结构，不能在不改 Quartz 核心类型的前提下直接塞入任意业务字段。
- `FolderPage` 根据真实目录结构自动生成列表页，因此目录名就是最终 URL 和页面层级。
- 当前知识类内容约 157 篇、文章类内容约 9 篇，目录迁移和链接修复必须可批量执行，不能依赖手工逐个调整。
- 需求已确认真实迁移且不兼容旧 URL，因此本次可以把实现重心放在新结构落地，而不是兼容层。

## Goals / Non-Goals

**Goals:**
- 提供可配置的全站固定顶部导航，并覆盖首页、知识库、文章库和文章详情页。
- 将首页升级为品牌化落地页，包含头像、标签语、简介和 3 篇精选文章入口。
- 将内容真实迁移到 `知识库` / `文章库` 两层结构，复用 Quartz 现有 FolderPage 能力生成新列表页。
- 让首页、列表页、文章页共享统一视觉语言，但保留不同的功能密度。
- 保持实现范围在 Quartz 现有组件、布局和静态构建体系内，不引入额外服务。

**Non-Goals:**
- 不做示例网站的逐像素复刻。
- 不新增后台、数据库、CMS 或运行时接口。
- 不为旧 URL 提供重定向、别名兼容或自动跳转。
- 不重写 Quartz 全部渲染流程，只在现有扩展点上做最小必要定制。

## Decisions

### 1. 业务配置采用“项目自定义配置模块 + `quartz.config.ts` 聚合导出”

站点导航、Hero、精选文章 slug 属于博客业务配置，而不是 Quartz 核心的全局配置字段。实现上将新增一个项目本地的类型化配置模块，供自定义组件和布局读取；`quartz.config.ts` 继续作为统一入口，负责导出 Quartz 原生配置并聚合引用业务配置。

选择这个方案的原因：
- 避免直接修改 `quartz/cfg.ts` 的 `QuartzConfig` 类型，降低和上游 Quartz 的耦合。
- 仍然满足“站点总配置可编辑”的需求，维护者只需在同一组配置文件里维护导航、Hero 和精选文章。
- 自定义组件读取配置时不需要通过 frontmatter 绕路，也不会把站点级内容混进 `content/index.md`。

备选方案：
- 直接扩展 `QuartzConfig`：可行但侵入 Quartz 核心类型，后续升级成本高。
- 把导航/Hero 写进首页 Markdown frontmatter：不适合全站导航，也不利于精选文章的统一维护。

### 2. 固定导航和首页 Hero 使用自定义 Quartz 组件接入 `header` / `beforeBody`

`renderPage` 已经为所有页面提供统一的 `header` 和 `beforeBody` 插槽，因此全站固定导航适合放到 `header`，首页 Hero 适合放到 `beforeBody` 中并通过 `ConditionalRender` 限制为首页生效。

选择这个方案的原因：
- 复用 Quartz 现有布局扩展点，不需要改 emitter 或新建独立页面渲染链路。
- 首页 Hero 可以直接读取 `allFiles` 和站点配置，生成精选文章卡片，而不需要额外数据源。
- 页面是否显示某个控件可以通过 slug 条件判断，而不是拆分多套渲染模板。

备选方案：
- 直接改 `renderPage` 支持多模板：灵活，但对当前需求过重。
- 继续用 `content/index.md` 纯 Markdown 描述首页：无法稳定实现 Hero、头像和精选文章卡片，也不便于配置化。

### 3. 首页采用 slug 定向布局收缩，而不是新增单独渲染模式

Quartz 默认会始终渲染左右栏容器，因此首页若要做成更接近落地页的视觉，需要对首页 slug 定向调整 grid 和 sidebar 显示规则。实现上会在首页将左右栏组件数组收空，并通过首页专属样式把 `#quartz-body` 切换成单列/弱侧栏布局。

选择这个方案的原因：
- 可以在不改 `Body.tsx` 和 `renderPage.tsx` 的前提下获得明显不同的首页结构。
- 只对首页生效，列表页和文章页仍沿用 Quartz 原有骨架，回归成本低。
- 风险集中在样式层，便于调试和回退。

备选方案：
- 修改 `renderPage` 跳过左右栏容器：侵入核心渲染文件，没有必要。
- 保留空侧栏：首页主体宽度受限，无法形成明显的 Hero 视觉。

### 4. 内容结构采用真实目录迁移到 `知识库` / `文章库`

目录将从当前的顶层结构迁移为：
- `content/知识库/人工智能` <- `content/00人工智能`
- `content/知识库/工具使用` <- `content/01工具使用`
- `content/知识库/专业学习` <- `content/02专业学习`
- `content/文章库/归档文章` <- `content/归档文章`
- `content/文章库/技术文章` <- `content/技术文章`

选择这个方案的原因：
- `FolderPage` 直接从真实目录生成页面，真实迁移后新的知识库/文章库层级会天然生成对应列表页和子目录页。
- 需求已经接受旧 URL 失效，因此没有必要再引入虚拟路由或映射层。
- 迁移后的导航、首页链接和正文内链接都以新 slug 为准，语义更清晰。

备选方案：
- 仅在前端重命名显示文案，不调整目录：URL 与信息架构不一致，无法生成新的知识库/文章库父级页。
- 通过别名兼容旧目录：与“不兼容旧 URL”的确认取舍冲突。

### 5. 精选文章卡片通过配置 slug 与 `allFiles` 解析生成

精选文章不会新建数据表，而是由站点配置提供 3 个 slug，自定义首页组件在构建时从 `allFiles` 中定位对应内容，读取标题、日期和描述等已有元数据进行渲染。

选择这个方案的原因：
- 完全复用现有内容和 Quartz 已解析的数据。
- 配置变更后无需改组件源码，符合需求中的“站点总配置可替换精选文章”。
- 无需再维护一份重复的首页文章摘要数据。

备选方案：
- 在首页组件里硬编码链接：维护成本高，不符合配置化要求。
- 单独维护首页精选数据文件：和现有内容数据重复，收益低。

### 6. 视觉统一通过主题 token + 少量自定义样式完成

视觉更新将以 Quartz 现有主题变量为基础调整字体和颜色，并为导航、Hero、按钮、卡片和首页背景补充少量组件级样式。页面功能密度则通过 `quartz.layout.ts` 对不同页面类型收敛控件组合来实现。

选择这个方案的原因：
- 可以保留 Quartz 的阅读能力和响应式基础，不需要推翻 `base.scss`。
- 样式变更集中在少量变量和新组件样式上，易于回归。
- 视觉和结构分离，后续再微调品牌风格时改动范围小。

备选方案：
- 全量改写 `base.scss`：工作量大，回归风险高。
- 另起一套前端页面：超出当前项目边界，也会削弱 Quartz 现成能力。

## Risks / Trade-offs

- [旧 URL 全部失效] -> 通过明确目录映射、同步更新导航与首页入口、批量检索旧路径引用来降低遗漏风险。
- [首页样式特化依赖 slug 选择器] -> 将首页专属类名和选择器限制在自定义组件范围，避免污染普通页面布局。
- [精选文章 slug 配错会出现空卡片] -> 在实现中为缺失 slug 提供清晰占位或构建期告警，不静默失败。
- [157 篇知识内容迁移时可能漏改内部链接] -> 用仓库级搜索批量替换旧目录前缀，并在构建后抽查首页、知识库、文章库和文章详情页。
- [页面控件收敛后可能影响部分阅读习惯] -> 仅保留真正需要的阅读辅助项，把 Explorer/Graph/RecentNotes 这类工具从首页和列表页移除，文章页再保留必要项。

## Migration Plan

1. 新增业务配置模块、自定义导航组件和首页 Hero 组件，并在 `quartz.layout.ts` 中接入新的页面分层规则。
2. 调整主题变量和自定义样式，让首页、列表页、文章页先具备统一视觉骨架。
3. 执行内容目录真实迁移到 `知识库` / `文章库` 结构，并同步更新 `content/index.md`、导航配置和正文中的旧路径引用。
4. 配置头像、Hero 占位文案和 3 个精选文章 slug，确保首页与导航都指向新结构。
5. 运行 Quartz 构建并手工验证首页、知识库、文章库、文章详情页以及移动端表现。

回退策略：
- 这是纯静态站点改动，没有数据迁移状态；若上线结果不符合预期，直接回滚整组提交即可。
- 目录迁移、导航配置和首页链接必须作为同一批改动回滚，避免出现新旧路径混用。

## Open Questions

- Hero 文案、个人标签语、个人简介和头像最终取值仍是 `【待确认】`，当前设计默认保留配置占位。
- 3 篇精选文章的最终 slug 待确认，当前方案只规定配置机制和数量约束。
- 文章页是否继续暴露暗色模式切换不是硬性需求；实现阶段默认以浅色主视觉优先，是否保留入口可在开发时根据实际效果决定。
